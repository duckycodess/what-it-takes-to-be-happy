# Design

## Context

See [proposal](proposal.md). The JSON contract in `docs/content-contract.md` and validator already model chapters, scenes, source levels, dialogue standing, visuals, optional details and authoring-only provenance. The renderer writes all scenes into one HTML document; JavaScript changes visibility, not prose. The art coverage map explicitly lists 34 drawn storyboard beats and 53 undrawn. The editorial source is `docs/storyboard.md`; `docs/coverage.md` maps assignment, concepts and member positions to stable beats. No deltas exist under `docs/notes/deltas/` as of this issue.

## Goals / Non-Goals

**Goals:** Transfer the exact audited main-path argument, preserve editorial standing and stable references, eliminate final-facing fixture/placeholder surfaces, make meaningful original visual changes and verify complete reading modes.

**Non-Goals:** A different prose argument, equal speech quotas, fabricated quotations or biographies, live Google Docs import, a new runtime framework, deployed release or offline submission. #7 owns published-output cleanup.

## Decisions

1. **Author in checked-in JSON, not runtime Markdown.** The storyboard is editorial truth; a bounded one-off transform may help transfer blockquotes. Keep `s001`–`s087` and `c0`–`c6` as immutable story IDs. R01–R32 retain their audited registry data. Expand cast from four to eight (`nessa`, `dino`, `ivy`, `marco`); the unseen narrator is never a cast entry. Replace fixture-ID expectations in validator, reorder, render, browser and font tests with final-content checks, while keeping deliberately broken fixtures. Alternatives: hand duplication (drift-prone), runtime parser (unnecessary dependency).
2. **Represent the actual reading order.** Add a required `mainPath` sequence of `{kind, index}` references to each scene's `narration`, `dialogue` and `limitations` arrays; validate that each array element is referenced exactly once, of its declared kind, with no duplicate/out-of-range index. Render in that sequence rather than the fixed narration→dialogue→limitations order (while retaining citations/concepts/details after the scene's ordered essential blocks). This preserves 20 dialogue-before-narrator and five caveat-before-dialogue beats, including `s086`'s question before its answer. Update schema, validator, renderer, docs and tests together; keep existing fields/provenance semantics rather than duplicating strings in the sequence.
3. **Make landing and connective prose explicit.** `s001`'s question goes to `project.question`; its introduction ('Three of us tried…') to `s001.narration`; its member names and 35–44-minute sentence to the landing's existing member list and `project.readingTimeEstimate`, not a repeated beat paragraph. The first Begin target stays `s001`, and the editorial comparator documents this one split. Author 14 chapter opening/closing bridges from the storyboard Transition metadata without claiming they were blockquote prose, and add provenance on chapter IDs pointing to the storyboard/brief. Compare every remaining storyboard blockquote paragraph in scene order and maintain an explicit allowlist for the landing split and authored bridges. The c0 navigation label is 'Opening', without a numeric chapter; c1–c6 display 1–6.
4. **Draw truthful motifs, not decorative coverage.** At least 86 of 87 beats get original drawn compositions; reuse a motif only if its geometry genuinely serves the beat, and add focused SVG motifs for the gaps. `s087` alone is an intentional text-only register handoff. Add `visual.artAbsence: null | 'pending' | 'text-only'` to the content contract: drawn visuals require null; undrawn visuals require a declared reason; final content forbids pending. Renderer omits the visual frame entirely for text-only material and shows the pending notice only in a draft. Source register remains readable. Friend figures get a visible and accessible 'fictional illustration' label distinct from members' nametags; `s086` may display friend names outside the drawing but not above those heads. Use `docs/art-requests.json` and isolated `codex/art-<id>` branch only if a generated image is truly needed; existing authored SVG is sufficient by default. Preserve settled/reduced-motion equivalence and document motif reuse honestly.
5. **Scope concepts and supplementary detail.** Represent the storyboard's lens labels as concept entries where a beat cites them; draft each explanation/application/question using only the audited storyboard and coverage matrix, but keep essential treatment in main prose because the renderer currently shows only names. Audit every lens against `docs/coverage.md` and avoid assigning theorists a claim the notes do not support. Optional disclosures attach to s007, s010, s020, s028, s038, s050, s051, s062, s064 and s069; s087 points to the full source register rather than inventing another detail. Existing native `details` and source links suffice; none gates Next.
6. **Measure what the visitor actually reads.** The storyboard tool measures its own blockquote corpus (8,627 words / 35–44 minutes at 200–250 wpm). Add a JSON main-path count that includes the actual landing introduction, chapter bridges and scene blocks, but not duplicate landing question, sources, captions or optional detail; derive the displayed range from that count. Reconcile `s001`'s editorial estimate, `docs/coverage.md`, the storyboard count assertion and the JSON landing/test expectation explicitly if the added bridges change the range; do not claim 35–44 while counting more words. Preserve source quotations and their punctuation (including em dashes and ∼) rather than silently changing evidence: both font cmap tables show those glyphs in the bundled DejaVu fallback, so update the font-coverage test to assert the actual fallback set and inspect the rendered punctuation at both widths.
7. **Verify editorial and browser behavior separately.** Add tests for all storyboard IDs/order, blockquote transfer and distinct ordering, provenance, source levels, final art absence rules, concept coverage and no fixture prose. Run `npm run check`, storyboard tools, strict OpenSpec validation, a real narrow/wide browser for keyboard, details and reduced motion. Record print evidence from stylesheet-structure and beforeprint tests; if this WSL Chrome cannot emulate print, explicitly state that no rendered print preview was inspected. Record source samples from each chapter, actual time and limitations in `docs/verification.md`. No linter/typechecker is configured; `npm test` runs parser checks.

## Risks / Trade-offs

- **Long essay with 87 beats** → Use chapter shortcuts and continuous reading view, retain 35–44 minute estimate if measured; do not cut perspectives to hit an old target.
- **Automated import scrambles dialogue, quotation marks, source metadata or emotional states** → Compare each beat's ordered main-path strings and mappings to the storyboard and hand-read representative/sensitive scenes across chapters, especially `s038`, `s053`, `s061`–`s070`, `s075`–`s087`.
- **Art effort scales out of proportion** → Reuse motifs only where explanatory truth matches; intentional text-only presentation is honest, generic decorative repetition is not. Inspect phone and desktop.
- **Large content makes fixtures/tests stale** → Replace fixture-specific assertions with semantic tests or separate fixture data; keep build/reader contracts intact.

## Migration Plan

Replace the fixture on this isolated branch in logical commits (content first, then art/verification where feasible). Build regenerates `dist/` from the same JSON. Revert the commits to restore fixture; no persisted user data or migration exists. Deployment is #7's release responsibility.
